# 예측 가능한 매매 계약서

## 봉인 선언

이 문서는 TradingDashboard 자동매매 전략의 핵심 계약이다.

예측 가능한 매매가 아니라면 매수하지 않는다.
여기서 예측 가능하다는 말은 감이 아니라,
진입 전 손실과 기대수익을 숫자로 설명할 수 있다는 뜻이다.

전략은 이 문서를 우회해서 매수 신호를 만들 수 없다.

## 핵심 원칙

매수 전에 반드시 다음 질문에 숫자로 답해야 한다.

```text
어디서 사는가?
왜 거기서 사는가?
틀리면 어디서 나오는가?
틀렸을 때 몇 % 잃는가?
맞으면 어디까지 가는가?
맞았을 때 몇 % 먹는가?
손익비가 최소 1.5 이상인가?
거래량이 다시 붙고 있는가?
상위 시간틀이 허락하는가?
익절 위치가 기준가/N자/박스/거래량 신호 중 하나 이상으로 설명되는가?
```

이 질문에 답하지 못하면 매수 금지다.

## 매도 원칙 연결

예측 가능한 매매는 진입 전에 매도 이유도 설명되어야 한다.

```text
손절 = 기준가 이탈 또는 강한 이탈
익절 = 위쪽 기준가, N자 목표, 박스 목표, 거래량 증가 신호
홀딩 = 원웨이 또는 트랩 회복 패턴
비상청산 = 기준가가 애매하거나 심리가 무너진 경우의 고정 손절/익절
```

고정 퍼센트는 기본 매도 원칙이 아니다.
고정 퍼센트는 구조 기준이 애매하거나 대응을 놓쳤을 때 사용하는 마지노선이다.

## 차트 스냅샷 컨텍스트 원칙

전략 검증용 차트 스냅샷은 단순히 고정 봉수만 맞추면 안 된다.

기준마디를 보려면 출발 전 바닥의 60선이 보여야 한다.
따라서 15분봉, 1시간봉 등 확인용 차트는 다음 조건을 우선한다.

```text
출발 전 바닥 60선이 보이는가
60선이 누워 있다가 돌아서는 구간이 보이는가
거래량이 잠잠했던 구간이 보이는가
첫 번째 거래 유입과 기준마디 시작점이 보이는가
현재 위치까지 한 화면에서 이어지는가
```

고정 봉수는 이 조건을 만족시키기 위한 기본값일 뿐이다.
바닥 60선이 보이지 않으면 봉수를 늘려야 한다.

```text
15분봉 확인용 기본값: 500봉
1시간봉 확인용 기본값: 240봉
필요 시 바닥 60선이 보일 때까지 700봉 이상으로 확장
```

이 원칙은 이미지 검증용 스냅샷에 적용한다.
전략 엔진의 실시간 숫자 계산은 필요한 데이터만 별도로 유지한다.

## 15분 60선 기준 원칙

우리 전략에서 구조 판단의 하한선은 15분봉 60선이다.

일봉은 종목을 볼 이유와 큰 기준봉/새 마디 출발 후보를 찾는 시간틀이고,
15분봉은 그 새 마디가 실제로 살아 있는지 확인하는 기준 시간틀이다.

따라서 15분봉 60선은 다음 역할을 가진다.

```text
새 마디가 살아 있는지 확인하는 기준선
눌림이 정상 눌림인지 훼손인지 나누는 기준선
확인 구간과 매수 준비 구간을 나누는 기준선
하위 시간틀 진입 신호가 의미 있는지 판정하는 기준선
```

15분봉 60선 아래에서는 매수를 서두르지 않는다.
이 구간은 매수 구간이 아니라 회복 확인 구간이다.

```text
15분 60선 위
= 상위 구조 생존 가능

15분 60선 근처
= 눌림/회복 확인 구간

15분 60선 아래
= 마디 훼손 또는 회복 대기
```

5분봉, 3분봉, 1분봉은 15분봉 60선 기준을 통과한 뒤에만 진입 타이밍으로 사용한다.

```text
5분 / 3분
= 거래량 감소 후 재유입 확인
= 기준가 회복과 작은 마디 확인

1분
= 실제 진입 타점
= 짧은 손절 가능 여부
= 체결/호가/거래량 재점화 확인
```

하위 시간틀은 상위 구조를 뒤집지 못한다.
15분봉 60선 기준이 무너진 상태에서 1분봉이 좋아 보여도,
그것은 매수 신호가 아니라 회복 확인 신호로만 본다.

## 최종 봉인 원칙

좋아 보인다는 이유로 매수하지 않는다.

다음 값이 없으면 매수하지 않는다.

```text
EntryPrice
StopPrice
TargetPrice
StopRiskPercent
TargetProfitPercent
RiskRewardRatio
```

전략은 매수 신호를 만들기 전에 반드시 이 계약을 통과해야 한다.

## 주문 의도 계약

전략과 AI 차트검토는 주문 의도까지 낼 수 있다.
하지만 주문 의도는 주문 실행이 아니다.

```text
StrategyOrderIntent.Watch
StrategyOrderIntent.PrepareBuy
StrategyOrderIntent.BuyReady
StrategyOrderIntent.BuyNow
StrategyOrderIntent.PrepareSell
StrategyOrderIntent.SellNow
```

`BuyNow`는 다음 의미다.

```text
전략/AI 관점에서 주문 문을 두드릴 수 있는 상태
```

`BuyNow`가 나와도 실제 주문은 바로 나가지 않는다.
반드시 다음 문을 통과해야 한다.

```text
Engine Start ON
Live Orders ON
분봉 장부 READY
예산/슬롯 OK
중복매수 정책 OK
손절 앵커 존재
시장상태/주문시간 OK
RiskGuard 통과
```

따라서 최종 구조는 다음이다.

```text
차트/전략/AI 판단
→ OrderIntent
→ RiskGuard
→ 주문
```

주문 신호는 넣는다.
단, 주문 신호는 문지기를 통과해야만 실제 주문이 된다.
